# 云台相机联调接口

光电视觉默认仍显示原有七路协同回传；页面顶栏切换到云台相机时，在同一主屏位置显示独立云台视频和控制面板。云台不加入现有 UAV/USV 信号源列表。

## 平台 API

- GET /api/gimbal-camera/status：读取配置、在线状态、浏览器可播放流地址、云台姿态和镜头状态。
- POST /api/gimbal-camera/commands：发送设备控制指令。请求示例：{"command":"PTZ_MOVE","parameters":{"direction":"LEFT","speed":7}}。

平台 API 仅接受代码白名单中的命令，且每条命令还必须出现在适配器当前 `supportedCommands` 中；这避免把平台界面占位能力误认为 A10TR 已支持能力。当前 A10TR 实际仅声明 `PTZ_MOVE`、`PTZ_STOP`、`PTZ_HOME`，变倍关闭。控制请求要求已登录并携带平台 CSRF 令牌。

## 协议网关适配

后端以网关屏蔽不同 ViewLink/云台型号的协议差异：

- GET {gateway-url}/status 返回 GimbalCameraStatusResponse JSON。
- POST {gateway-url}/commands 接收 {commandId, command, parameters}，返回 {commandId, command, status, detail}。

运行配置：`APP_GIMBAL_CAMERA_ENABLED=false`（联调阶段保持关闭）、`APP_GIMBAL_CAMERA_GATEWAY_URL=http://10.16.88.211:8780`、`APP_GIMBAL_CAMERA_GATEWAY_TOKEN`。令牌通过 `X-Adapter-Token` 请求头读取环境变量发送，不写入仓库。状态读取与控制开关分离；只有确认安全后才设置 `APP_GIMBAL_CAMERA_ENABLED=true`。当前前端的 `playbackUrl` 作为 HTML video 的直接 src 使用，必须是浏览器/运行环境可直接播放的媒体 URL；RTSP 地址不能直接作为浏览器 video 源。云台 JPEG 画面仍由独立视频 Gateway 通道提供，不依赖该 TCP 控制适配器的 `playbackUrl`。

2026-10-28 已从当前 Windows 平台主机携带认证头读取 `/status`，HTTP 200。状态报告：云台 TCP 连通性探测成功（`192.168.2.119:2000`），但未建立持久 TCP 会话；适配器 `enabled=true`、`controlEnabled=false`、`motionActive=false`、`safetyFault=null`、看门狗超时配置为 0.8 秒；当前只声明 `PTZ_MOVE`、`PTZ_STOP`、`PTZ_HOME`，`zoomControlEnabled=false`。同事确认 `tcpReachable` 是短连接探测结果，而 `tcpSessionOpen=false` 只表示尚未按需建立可复用的控制会话，不代表故障；首次有效命令才会建立会话，`lastTxAt`/`lastRxAt` 为空在首次控制前属预期。此状态读取没有发送控制指令。

平台在默认控制关闭时仍可读取适配器状态；任何平台控制请求会在后端被拒绝。适配器报告的 `supportedCommands` 和 `controlEnabled` 用来进一步锁定前端可操作项，后端发送前也会重新读取状态并校验设备可达、控制已启用和指令已声明支持。未经适配器支持的界面按钮保持禁用。适配器命令请求为 `{"commandId":"...","command":"PTZ_MOVE","parameters":{"direction":"RIGHT","speed":3}}`；速度是 1–10 的抽象坐标偏移等级（默认 3），不能解释为物理转速。`PTZ_STOP`/`PTZ_HOME` 可使用空参数。HTTP 200 的 `status=sent` 仅表示 TCP 发送流程完成，不是设备 ACK，也不证明物理运动；平台后端当前会生成唯一 `commandId` 并代理请求。适配器参数错误 400 和控制关闭 503 会映射回平台 API 的相应状态码；认证或其他上游错误统一作为网关错误处理。

### 控制安全验收（2026-10-28 同事确认）

- 适配器默认 `A10TR_CONTROL_ENABLED=0`；只有在启动配置显式设为 1 并重启适配器后才允许发命令。平台侧 `APP_GIMBAL_CAMERA_ENABLED=false` 继续保持，直到下列实机安全验收完成。
- MOVE 按住期间必须重复发送以续租；当前页面按 300ms 周期尝试续发，并经单一有序请求队列串行发送。松开时先取消后续续租，再把 STOP 排在任何已发出的 MOVE 请求之后，避免旧 MOVE 在 STOP 后到达；单次请求失败会结束续租并尝试 STOP。适配器看门狗租约配置为 0.8 秒、每 50ms 检查，到期尝试发送停止帧，发送失败会置 `safetyFault` 并约 0.25 秒后重试。浏览器断连不会触发即时回调，只有续租中止后租约到期才会尝试停止。
- 看门狗与断连停止尚未实机验证；适配器进程退出、主机断电或网络中断都可能令停止帧无法送达，故 0.8 秒不等于已保证的物理停止时间。现阶段不得据此宣称具备独立人工授权、物理互锁或失联安全保证。
- 受控验收需在云台周边清场、低速/短按、可人工断电或急停的条件下，由现场操作员依次验证 MOVE→松手 STOP、HOME、续租停止后的看门狗、浏览器/客户端断连后的停止尝试、网络异常和 `safetyFault` 告警；记录请求、响应、设备实际动作、回包及停止耗时。全部通过并获得现场安全确认前，不开启平台控制；变倍保持禁用。

## A10TR 视频帧接入

已按提供的 `gimbal_ws_outer_sample.json` 和 `gimbal_ws_frame_sample.json` 样例加入独立视频接收通道。完整 Gateway 消息是文本 JSON：顶层 `message_type=camera_frame`，帧数据位于 `data`；抽取帧样例是同一 `data` 对象的扁平形式。接收器只接受 `vehicle_id=gimbal_01`、`stream_id=gimbal_01_a10tr`、`encoding=image/jpeg`，并校验 JPEG 首尾标记，不进入原六路相机目录。

- 上游地址默认 `ws://10.16.88.211:8765/ws`，可用 `APP_GIMBAL_CAMERA_STREAM_WS_URL` 覆盖。
- `APP_GIMBAL_CAMERA_STREAM_ENABLED` 默认开启；接收器只监听 Gateway 广播，不发送订阅或控制消息。
- `GET /api/gimbal-camera/frame` 返回最近 JPEG；前端独立画面约每 100ms 拉取新帧，支持无新帧时返回 204。
- 云台画面左上角的 FPS 按浏览器收到的新帧时间滚动计算（5 秒窗口），无新帧超过 1.2 秒显示 `-- FPS`；不是写死 Gateway 报告值。
- 端到端显示要求 Gateway 实际向 `/ws` 广播 `camera_frame`。若网关只发 `gateway_hello`、`fleet_snapshot`、`perception_targets`，界面会保持等待帧状态。
- TCP `192.168.2.119:2000` 控制协议与视频 WebSocket 分离。2026-10-27 的 `viewpro_control_tcp2000_retest.pcap` 已确认控制端双向 TCP 应用数据完整到达；初步帧统计与动作对应关系见下方复测结果。控制按钮仍保持禁用，直至时序/回包语义和失联停止保护实机验证完成。

## 控制网络路径核验

页面控制链路设计为：浏览器 POST /api/gimbal-camera/commands → 平台后端 → 部署在控制端或可达控制网的 HTTP 协议适配器 → A10TR 192.168.2.119:2000 TCP。视频 WebSocket 与控制 TCP 是两条独立链路；当前仓库仍未实现最后一跳的 A10TR TCP 协议适配器。

2026-10-27 分开核验的结果：当前平台 Windows 主机可达视频 Gateway 10.16.88.211:8765，但到控制端 192.168.2.118 的 TCP 22/2000 及云台 192.168.2.119:2000 均超时；这表示平台主机不能直连控制网段。Ubuntu 控制端到云台的 TCP 路径已由路由表及 `nc` 成功确认。2026-10-28 又从 Windows 平台主机携认证头直连控制适配器 `GET /status` 得到 HTTP 200，故 Windows→适配器 HTTP 路径已确认；但平台应用自身的代理状态 API 尚需在配置并重启服务后通过已登录页面复测。仓库默认 `APP_GIMBAL_CAMERA_ENABLED=false`、网关地址为空；控制按钮继续禁用。

右转、变倍加/减和回中的带标记单项补抓已完成，结果见下方；HTTP 适配器也已部署并从 Windows 主机直连验证。下一步是完成已列出的受控 MOVE/STOP/HOME、看门狗和断连实机验收，并在不启用控制的前提下配置/重启平台后端，验证已登录页面的状态代理链路。只有安全验收通过并获得现场确认后，才分别开放适配器与平台控制开关；变倍仍待厂商参数确认。

### 控制抓包复测结果（2026-10-27）

对 `viewpro_control_tcp2000_retest.pcap` 完成 TCP 双向重组：控制端 `192.168.2.118:45810` → 云台 `192.168.2.119:2000` 共 290 个 `EB 90` 帧，TCP 序列无缺口，所有帧外层校验和通过；其中 239 个 11 字节轮询帧、44 个 24 字节控制帧、7 个 12 字节附加帧。设备→控制端收到 31,552 字节应用数据，回包不是 `EB 90`，而以 `55 AA DC` 开头，含 7 字节短帧及约 47 字节状态帧，因此不能把反向数据误判为“无应答”。

按首份操作记录对齐后，方向控制帧为 `0D`，每条 `0D` 后均出现轴值清零的 `01` 帧（`EB 90 14 55 AA DC 11 30 01 ... 20 3D`）。官方 ViewLink 协议示例将 `01` 定义为云台停止，且本次线上帧与该示例一致；首份综合抓包的帧次数与用户操作次数存在偏差，现以带明确动作标注的单项补抓进一步核对，不能单靠协议帧数统计用户按键次数。

设备回传包含重复出现的 `55 AA DC 04 AC 30 98` 短帧及 `55 AA DC .. 40` 状态帧；短帧常紧随控制帧，但目前无法证明其是 ACK、状态通知还是其他响应。变倍操作后还观察到 `EB 90 08 55 AA DC 05 1C 0F 00 16 21` 附加帧，语义未确认。不能据此宣称回包字段、角度/变倍状态或所有按键语义已完全解码。

#### 单项补抓：右转、变倍、回中

收到 `viewpro_control_right_retest.pcap` 及操作说明“右转×3、变倍加×1、变倍减×3、回中×3”。该 TCP 会话双向序列无缺口；控制端解析出 263 个 `EB 90` 帧，外层校验和全部通过（239 个 11 字节轮询帧、20 个 24 字节控制帧、4 个 12 字节附加帧），设备回传 27,023 字节。

- 右转×3：观察到 3 个 `0D` 控制帧，每次之后分别约 156ms、188ms、223ms 出现轴值清零的 `01` 停止帧。此次右转 RC 值为 `0x0668`（十进制 1640）；首份综合抓包为 `0x06E0`（1760），都高于中位值 1500，数值差异反映控制量不同，不应硬编码成一个固定右转值。
- 变倍加×1：单次按住期间出现 4 个相同 `0F ... 02 60` 帧（间隔约 0.22–0.36 秒），松开后约 0.50 秒发出 `0F ... 00 40`。这是“一个用户动作对应多条重复协议帧”的实证，前端应按按住/松开处理，而不是把每条帧计为一次点击；停止字段仍需实机验证。
- 变倍减×3：观察到 3 个 `0F ... 02 20` 帧，每个约 0.50 秒后跟随 `0F ... 00 40`。
- 回中×3：观察到 3 个 `04` 帧，与用户记录的三次操作一致。

#### 厂商协议交叉核对

Viewpro《Viewlink Communication Protocol》§3.3.1.6 将 `0D` 定义为 Manual RC 控制：偏航/俯仰速度字段单位为 0.1°/s（零值使用系统默认速度），RC 位置字段范围 1100–1900；这与抓包中 1500 中位、1240 左/上、1640/1760 右、1760 下的轴值一致。协议示例 §4.1 将 `01` 定义为 Stop、`04` 定义为 Recenter；本次抓到的内层命令及校验字节与示例完全一致。因此方向控制、松开停止和回中已获得厂商协议示例支持。TCP 外层格式 `EB 90 + 串口协议数据体 + 数据体字节和低 8 位校验` 与此前用户提供的 A10TR 说明书 §4.4 及本次抓包一致。

变倍仍有不一致：该协议示例 §4.2 给出变倍加 `02 78`、变倍减 `02 38`、停止 `00 00`；本设备抓包是加 `02 60`、减 `02 20`、释放 `00 40`。方向与操作顺序吻合，但这些参数/释放值与通用示例不同，可能与型号/固件/速度设置有关；在 Viewpro 对 A10TR 固件确认或观察到镜头确实停动之前，不能把 `00 40` 当作已确认的变倍停止命令。

设备端仍回传 `55 AA DC` 短帧和状态帧。单项补抓里，每条 24 字节控制帧后 13–65ms 均观察到 `55 AA DC 04 AC 30 98`；4 条 12 字节附加帧后 11–20ms 观察到 `55 AA DC 04 AC 1C B4`。这两种 7 字节短帧均满足 `payload[0] XOR payload[1] XOR payload[2] = checksum`，本抓包解析出的 275 条 7 字节短帧校验全通过。因此它们是强相关的 ACK 候选，但由于没有厂家定义或错误响应对照，仍不能确认其确切语义/成功状态。状态帧字段尚未解码。

当前平台安全状态也已核对：`APP_GIMBAL_CAMERA_ENABLED` 默认为 `false`，协议网关地址默认为空；后端仅向配置的 HTTP 适配器转发，不含 A10TR TCP 发送器，因此未配置时不会向设备发指令。前端方向键在按下时发送 `PTZ_MOVE`，并在松开/移出/取消/窗口失焦/页面隐藏/组件卸载时尽力发送一次 `PTZ_STOP`；相应保护已加单测。这只是客户端保护，服务端死手超时仍未实现。`01` 停止和 `04` 回中已由协议示例交叉确认；由于 A10TR 抓到的 `00 40` 释放值与通用示例不同，EO/IR 变倍按钮在 Viewpro 确认当前固件参数及实机验证前保持禁用；`04 AC` 短帧语义仍待确认。抓包命令仍可使用：`sudo timeout -s INT 120 tcpdump -i any -nn -s 0 -U -w /tmp/viewpro_control_right_retest.pcap 'host 192.168.2.119 and tcp port 2000'`；辅助脚本为 `ros-tools/capture_a10tr_control.sh`。
