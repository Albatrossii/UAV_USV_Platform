指标口径与边界

RTT 是应用层往返耗时，不是单向时延。超时率是未按时收到心跳回应的比例，不等于网络丢包率。未接入、未采样或重连时不填 0。

此卡只表示浏览器与平台后端的 WebSocket 通道，不代表 Unity 场景就绪、设备动作完成或真实无线链路质量。

分级规则 · 本项目建议值

  • 优秀RTT ≤ 100 ms
  • 良好100 < RTT ≤ 300 ms
  • 差RTT > 300 ms / 连续超时
  • 无连接连接断开或正在重连
  • 待检测已连接，暂无有效样本

已连接时，取最近 5 次探针（约 10 秒）的有效 RTT 中位数分级；断开状态优先。连续 3 次探针超时则显示“差 · 探测异常”，不沿用旧的低延迟值。

这是预览用的可调整阈值，不是通用标准。“优秀 / 良好 / 差”表示响应状况，不是带宽或无线信号等级。

简化展示与分级说明

默认只展示通信状态、连接类型、延迟等级、RTT 和趋势图。RTT 波动、心跳超时率、最近消息、重连次数、探测条与指标说明全部收进“详细指标”，点击后展开。

建议值：优秀 ≤100 ms；良好 >100 且 ≤300 ms；差 >300 ms。断开 / 重连显示“无连接”；没有样本显示“待检测”；连续 3 次探针超时显示“差 · 探测异常”。这些阈值不是 GitHub 项目或行业标准，后续可按部署环境调整。

本页保留上一版的设计参考，未引入这些项目的代码或依赖。

louislam / uptime-kuma ↗

提供 WebSocket 等服务监控、状态页和延迟图。参考它用颜色与时间序列表达连接是否稳定的思路。

websockets / ws ↗

官方示例包含往返时间计算和心跳存活检测。可作为后续实现参考，不是现成的前端卡片。

netn10 / Drone-Telemetry-Dashboard ↗

展示无人机遥测与 ping/pong 延迟思路。本方案直接标注 RTT，不把 RTT/2 当作已测出的单向时延。

cloudflare / speedtest ↗

提供带宽、延迟等互联网质量测量。它测的是到 Cloudflare 的链路，不能代替平台自己的 WebSocket 健康度；本页不启用外部测速。

真正接入时，指标这样取

  • 连接状态来自选定 WebSocket 的 open / close / error。
  • 最近消息用本地收到消息的时间计算；重连次数按当前页面会话累计。
  • RTT 需同一业务连接的应用层心跳与响应编号配对；目前未接入时应显示“—”，而不是 0。
  • 超时率按探测窗口内超时次数计算，不命名为 TCP 丢包率。不根据延迟猜测 4G / 5G 类型。
  • 只做内存中的短时探测窗口，不增加实验记录与回放。正常、波动、重连阈值需要结合实际环境标定。

当前所有状态与曲线都是固定示例。切换按钮只更新这个 HTML；不会探测网络、启动服务或修改现有 Vue 页面。
