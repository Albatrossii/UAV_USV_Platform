# UAV-USV 平台 P1-D4 本地语音到控制整链路验收 v1.0

日期：2026-09-24

## 1. 范围

D4 只组合复测已经完成的 D1、D3 与 P0：`录音 → 本地 ASR → 人工核对文字 → 本地 LLM 候选 → 冻结提案 → 人工确认 → Runner / Unity`。本阶段不扩大动作白名单，不允许 ASR 或 LLM 直接创建 execution，不修改 Runner 或 Unity 协议，也不新增独立页面。

## 2. 本机配置

- ASR：`Systran/faster-whisper-small`，revision `536b0662742c02347bc0e980a01041f333bce120`，CPU INT8，4 线程；4 个文件 SHA256 与仓库 manifest 一致。
- LLM：`Qwen2.5-1.5B-Instruct Q4_K_M`，通过 llama.cpp 在 `127.0.0.1:18083` 单实例运行。
- Java：`127.0.0.1:18081`，启用真实 ASR、local-llm 与 P0 控制。
- 前端：`127.0.0.1:5175`，启用 P1 BACKEND 与 Unity presentation v1。

## 3. 验收结果

1. 微信导出的 `Standard recording 6.mp3` 原文件被严格解码器返回 415 `VOICE_AUDIO_FORMAT_UNSUPPORTED`，未放宽服务端校验。
2. 对该文件做一次明确、临时的 MP3 重编码后，真实前端代理 → Java → Python ASR 返回 200；时长 5784 ms、18 个 Unicode 码点、模型别名 `whisper-small-cpu-int8-r1`，同键重放完全一致。
3. 本地 small 模型识别文字为“在暂停无人机和无人船的实验进行下一步”。用户核对后的文字进入本地 LLM，返回 `PAUSE / MISSION_PAUSE`。
4. 第一次解析发生在 `PREPARED`，页面正确禁止生成 PAUSE 提案。先通过既有 P0 手工 START 进入 `RUNNING`，再以相同文字发起新解析。
5. 第二次解析得到新的 PAUSE 候选；点击“生成待确认提案”后仍需人工确认。确认后 Runner 返回 `SUCCEEDED / SUCCESS`，页面进入 `PAUSED`，Unity 同步对 PAUSE 为 `NOT_REQUIRED`。
6. 首次解析超过前端等待窗口后，页面使用原请求恢复得到已完成候选，没有自动换键或重复计费。
7. 在同一 localhost 隔离环境中，使用真实物理麦克风说“暂停任务”；页面完成录音、真实 Whisper small 转写，并显示可编辑文字“暫停任務”。未使用文件上传、Mock 文本或假报告。
8. 转写文字进入真实本地 Qwen 适配器，生成 `PAUSE / MISSION_PAUSE` 候选。候选本身未直接执行；操作员点击“生成待确认提案”，再次点击“确认执行”。
9. Runner 返回 `SUCCEEDED / SUCCESS`，页面运行状态从 `RUNNING` 变为 `PAUSED`；该动作展示状态为 `NOT_REQUIRED`。数据库中的 `interpretationId → proposalId → executionId → commandId → runtimeRef → runtimeGeneration` 关联完整。
