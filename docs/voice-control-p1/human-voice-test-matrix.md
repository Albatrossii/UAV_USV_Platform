# 真人语音控制验收矩阵

更新日期：2026-10-11。仅用于本地 Unity 算法仿真，不连接真实 UAV、USV 或 ROS。

本次策略调整：按用户要求，本地仿真中新录制、明确且通过校验的语音指令取消人工确认，包括返航、降落、停止和包含这些动作的 2–4 步指令。手工文本、编辑后的文字、截断录音和恢复的待确认计划仍需人工核对；实机/网关控制不采用此免确认策略。下列历史通过记录不代表新策略已经通过真人复测。

## 执行规则

1. 每个批次开始前生成新场景，确认 `UNITY WEBGL ONLINE`、3 架 UAV 在原停机坪、3 艘 USV 在同岛岸边泊位且编号可见。开始任务后先起飞/离泊集结，集结完成再推进任务；单设备常规补测可在集结完成后进行。
2. 除明确要求连续录音的用例外，每句单独录音。说完后主动结束录音；当前硬上限为 59 秒。
3. 每次都分别核对：原始转写、规范化文字、设备类型和编号、动作、是否自动执行/要求确认、Unity 最终物理状态。
4. 本地仿真明确语音自动执行；整条顺序指令先完整校验，再严格串行执行。超过 4 步整句拒绝，不能截取前几步执行。
5. 出现错设备、否定指令被执行、需人工确认的手工/恢复计划提前执行、多次重复执行或虚假“完成”，立即判定失败并停止该批次。
6. 同一句在安静环境、日常口音、正常房间噪声下各测 1 次；核心用例建议各测 3 次。原始录音不要求保存。

结果填写：`通过 / 失败 / 阻塞 / 未测`。耗时从结束录音开始，到页面显示执行回执或确认卡为止。

## 判定口径

- **识别通过**：原始转写正确，或命中已批准的限定纠错，并且页面保留原始转写供核对。
- **解析通过**：类型、编号、动作和步骤顺序全部正确；只看文字相近不算通过。
- **控制通过**：本地仿真明确语音只自动执行一次；手工或恢复计划确认前零执行；歧义、否定、超步数等拦截类零执行；免确认策略不能扩展到实机/网关。
- **物理通过**：以 Unity 新帧为准。API 接收成功、按钮变色或出现“执行中”不能代替物理完成。
- **整项通过**：识别、解析、控制和物理结果全部通过。任一层失败，整项失败。
