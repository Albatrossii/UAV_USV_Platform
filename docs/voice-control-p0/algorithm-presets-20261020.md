# 2026-10-20 算法编号指令接入

运行版本为 `escort-20261020`。场景配置选择“10月20日指令版”，固定 3 UAV、3 USV、1 个护航目标和 1–2 个敌船；旧自适应算法仍可在版本选项中选择。已有旧场景需重置并重新生成才能切换版本。

## 使用

打开语音控制，说“执行第十三号指令”，输入同样的文字，或展开“算法指令 · 0–20”点击对应项。在后端登记的本地 Python 仿真中，正常结束录音后，明确的单条及2–4步组合指令自动解析、校验并执行，无需手动预览或再次确认；手动输入点击一次“执行”。底层仍经过后端冻结计划、版本/哈希校验及执行回执。成功表示算法已接受动作，不表示追击/围捕已完成。

编号支持中文、阿拉伯数字（含全角）和标准罗马数字（含 Unicode 形式），并兼容“号／条／个”量词。“执行第十三条指令”“执行第13号指令”“第十三个指令”“指令XIII”“执行第ⅩⅢ条命令”均对应13。也支持“请帮我执行第十三条指令吧”等明确说法；中文大写“壹拾叁”同样可用。自动提交前校验完整原文、编号、版本和各步骤；否定、疑问、歧义、录音达到时长上限、过期上下文及结果未知时不自动执行。历史恢复不自动重发，真实设备模式保留原有确认策略。

紧凑面板仅保留录音、识别文字、可折叠的编号目录和麦克风设置；空白时隐藏执行按钮，移除常驻示例和重复说明。麦克风测试录音仅在本页回放，不进入识别或执行链路。

解析不猜测缺失的编号：“执行一个指令／执行两个指令”属于数量描述，需明确编号；“第一个指令／第二个指令”分别对应1／2。否定句、疑问句、21以上编号、非标准罗马数字及有歧义的多个编号不会生成执行计划。

支持“开始任务，然后执行第一号指令”等 2–4 步组合。开始成功后，后续战术指令等待起飞、离泊阶段完成；等待超过整个序列的 600 秒上限则中断。单独在部署期间执行战术指令会提示 `PRESET_DEPLOYING`，不会提前作用于尚未出发的设备。

建议测试顺序：开始任务 → 等待出发完成 → 1 → 0 → 13 → 14 → 20 → 0 → 19。20 要求算法检测到可围捕目标；未满足时明确拒绝，不伪造执行成功。

### 岸边出发的敌我初始布局

编号算法在 `escortStartAtBerth=true` 时使用真实泊位与离泊入口确定外海方向。护航船在泊位前方约70米、避开离泊通道的位置集结；所有敌船位于护航船前方的外海扇区，双目标分别偏转±15°，不再绕护航船随机生成到基地一侧。

敌船距护航船不小于 `threatMinDistanceM`，同时必须在算法感知范围外；当前默认初始距离为224米。部署期间目标保持初始位置，设备起飞离泊完成后再进入接近、感知、守卫和按指令围捕流程。护航前进方向同步采用外海方向。布局只在生成时应用，不通过运行中重定位掩盖轨迹问题；旧版非岸边配置保留原始布局。

状态帧的 `initialEncounterLayout` 为 `SHORE_FORWARD` 时表示已采用此布局。新增专项覆盖1/2艘敌船、多个种子、海面高度偏移、部署连续性，以及13→14→20围捕完成后执行0恢复护航。

指令版阶段条改为“护航／守卫／追击／围捕／完成”，直接跟随算法模式和真实捕获结果。0号指令清除捕获和分组后，同步清除上一轮任务进度峰值；出发已完成时保留10%的出发进度，不再停留在99%。

## 实现与协议

- 原文件完整保存在 `algorithm-service/app/vendor/escort_commands_20261020.py`，SHA256：`df0ec7d6918242bc70de17dcf6a6c289ac2ed882f843326ed7131ef09701e94c`。不启动 Matplotlib 窗口，不模拟键盘。
- `CommandEscortAdapter` 将编号直接交给算法方法，转换原生坐标和平台坐标，反馈实际设备位置，按平台配置限制设备速度。Unity 使用现有权威帧通路显示角色、目标和位置。
- `GET /api/voice/algorithm-presets` 返回版本、编号、中文含义和原算法命令。前端菜单使用这份目录，不另存编号映射。
- 解析输出 `intent/action: ALGORITHM_PRESET`。冻结计划和 `algorithm.command.v1` 的 `parameters` 为 `{"presetId":13,"presetVersion":"escort-20261020"}`。沿用解释来源绑定、确认、幂等、运行代际、状态版本和命令回执校验。
- 后端对能力、版本、编号类型、目标存在性进行校验；Runner 再验证实际算法及当前状态。命令成功保持 `RUNNING` 并递增状态版本。
- 状态帧增加 `algorithmCommandProfile`、`algorithmMessage`、`algorithmMode`、`lastPresetId`、`fixedAssignments`、`deviceAlgorithmStates`、`operatorHold`。
- 算法角色与平台节点心跳分开显示。没有 ROS 节点心跳时通信状态仍可为“未知”，不能以仿真活动状态冒充在线。

## 适用范围

本接入服务于 Python/Unity 仿真。保留算法负责人原有数值模型，不宣称新增了真实海图避障能力。原有起飞、离泊、返航通路继续使用平台实现。

固定六设备算法不能把被操作员接管的设备视作仍在围捕：单设备悬停、返航等动作期间，整个战术计算暂缓，单设备控制继续执行；所有设备归队后恢复。页面显示该原因，期间拒绝新战术指令。

此次公开协议只开放0–20固定指令和对应中文语句；原脚本的任意文本命令、随机生成目标等键盘操作未作为任意代码/文本执行入口暴露。

- 原生空间统一按14米/单位换算，捕获半径36.4米，最小候选围捕环半径16.38米。目标和护航船的速度作反向换算以保留原物理速度；我方设备继续遵守界面配置的速度上限。

## 现场反馈修复：观察说明与敌船绕行

“执行围捕观察全过程。”和“执行围捕，观察全过程。”都解析为20号指令。“观察全过程”在这种完整句式中属于查看说明，不再当作第二个未接入动作；不额外创建相机或自动录像动作。前后端使用相同的完整匹配规则，否定、疑问、条件和额外动作不能被截掉后误执行。
