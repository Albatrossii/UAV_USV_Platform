# 语音大模型供应商无关接入准备

本阶段只建立前端接入边界和交互骨架，不选择供应商、不保存密钥、不调用付费服务，也不改变 Python 或 Unity 协议。

## 已准备的链路

```text
麦克风录音或文字输入
→ ASR 适配器（当前可使用独立 Mock）
→ 可编辑识别文本
→ 意图解析适配器（当前可使用独立 Mock）
→ 候选动作与安全检查
→ 现有 P0 冻结提案
→ 用户确认
→ 现有执行与 Unity 展示回执链路
```

模型不会直接调用 Runner。整队解析结果是 `START`、`PAUSE`、`RESUME`、`STOP` 四种候选动作；单设备控制另由后端确定性解析设备编号和受支持动作。两类指令都必须经过后端提案和人工确认。

否定表达、多动作歧义、尚未支持的攻击/围捕/撤退、目标缺失或多个设备目标都不会降级为整队动作。单设备控制仅在当前运行标记为 `_SINGLE_DEVICE`、指定目标属于本次运行且能力和命令类型匹配时生成候选；候选绑定运行代次及上下文版本，人工确认时再次校验。调度经过现有运行控制接口并等待权威设备回执，不直接绕过后端控制服务，也不回退到 ROS/Gateway 或整队控制。

## 本地启用

在 `frontend/.env.local` 中配置：

```dotenv
VITE_VOICE_P1_PREPARATION=true
VITE_VOICE_P1_MOCK=true
```

重启 Vite 后显示新输入区。`VITE_VOICE_P1_MOCK=true` 只验证前端状态和交互，不代表真实 ASR、LLM 或后端解析链路已接入。集成环境和生产环境应保持关闭，直到后端适配接口、供应商凭据、限流与审计策略确定。

没有后端上下文时仍可独立测试录音、文字编辑和解析状态，但“生成待确认提案”会保持禁用；只有读取到真实运行身份并通过现有 P0 检查后才能提交。

## 后续后端适配约束

前端只依赖 `VoiceIntelligenceAdapter`：

- `transcribe` 接收音频、区域和请求 ID，返回可编辑文本及模型标识。
- `parse` 接收文本、允许动作和设备快照，返回候选、需要澄清、不支持或不可执行。
- 供应商原始字段必须在后端转换，浏览器不得持有供应商 API Key。
- 后端必须重新校验运行身份、能力、权限和设备集合，不能信任浏览器解析结果。

前端已经提供平台后端 HTTP 适配器；后端按冻结契约实现两个接口后即可启用。现有输入组件、提案确认、Python Runner 和 Unity 展示链路无需按供应商重写。

前后端评审以 [P1 供应商无关接口契约](../voice-control-p1/interface-contract.md) 和同目录 JSON Schema、正反例为准。契约尚未由后端确认前，不应在集成环境开启真实后端适配器。
